# MSI 修复与强制安装工具（v3.1）

> 一款面向 Windows 运维 / 装机 / 售后场景的小工具：**一键修复 MSI 安装包"打开方式"损坏问题**，并支持**无视文件扩展名强制安装 MSI**。 单个 exe，免安装、免依赖，支持 Windows 7 / 8 / 10 / 11，32 位 / 64 位系统自动适配。

---

## 一、这个工具解决什么问题

客户机上常见的这几类故障，本工具可以一键处理：

- 双击 `.msi` 安装包**没有任何反应**，或者弹出"你要如何打开这个文件？"的选择框
- 右键菜单里的"安装 / 修复 / 卸载"消失或点了没反应
- 报错 **错误 1719**（Windows Installer 服务无法访问）、**错误 1723**、"Windows Installer 服务未正确安装"
- `msiexec /i` 手动执行也失败，提示"无法打开此安装程序包"
- 网上找的批处理、注册表文件点了没用（**绝大多数是因为漏了 UserChoice 校验这一关键步骤**，详见第八章）

同时提供一项附加能力：**把任意文件拖到程序图标上，就强制调用 msiexec 安装**——即使文件后缀被改成了 `.dat`、`.txt`、`.exe` 或干脆没有后缀，照样能装上。

## 二、功能特性

| 类别 | 能力 |
| --- | --- |
| **关联修复** | 重建 `.msi` → `Msi.Package` 关联；重建"安装 / 打开 / 修复 / 卸载"四个右键动词命令；恢复 MSI 默认图标 |
| **根因处理** | 删除 Win10/11 的 `.msi\UserChoice` 项（含哈希校验，这是批处理无效的根本原因）；同时处理当前用户与默认用户 |
| **组件重注册** | 执行 `msiexec /unregister` + `msiexec /regserver`；重新调用 `msi.dll` 的 `DllRegisterServer` |
| **服务修复** | 停止 / 启动 `msiserver` 服务；通过 API 与注册表双重方式恢复服务 `ImagePath` |
| **强制安装** | 无视文件后缀，直接调用 `msiexec /i "文件路径"` 安装；支持拖放、命令行、交互输入三种触发方式 |
| **免乱码设计** | **控制台全英文输出**（任何语言、任何精简版系统都不会乱码）；**日志文件全中文输出**（便于排查） |
| **权限自适应** | 修复时自动检测管理员权限并给出提示；安装时先普通启动，失败自动 `runas` 提权 |
| **全流程日志** | 每个步骤的成败、错误码、校验结果都写入日志文件，客户跑完把日志发回来即可定位问题 |

## 五、编译方法（Visual Studio 2015）

1. 打开 VS2015 → **文件 → 新建 → 项目**
2. 选择 **Visual C++ → Win32 → Win32 控制台应用程序**，随便起个名字（例如 `MsiFixTool`），点确定
3. 向导里直接点 **完成**，不要改任何选项（保持默认的"控制台应用程序"和 **Unicode 字符集**）
4. 把编辑器里自动生成的代码**全部删除**，将 `MSI修复工具_v3.1_最终版.cpp` 的内容**完整粘贴**进去
5. 顶部工具栏选择 **Release** + **x86**
   - 选 x86 编译出的是 32 位程序，能在 32 位和 64 位系统上通用，兼容性最好
6. 菜单 **生成 → 生成解决方案**，编译结果为 0 错误 0 警告
7. 生成的 exe 位于项目目录下的 `Release` 文件夹中，可直接拷给客户使用

> 代码中已通过 `#pragma comment(lib, ...)` 自动链接 `shell32.lib` / `advapi32.lib`，**不需要**手动配置附加依赖项。

## 六、使用方法

### 6.1 修复 MSI 打开方式（最常用）

1. 把 exe 拷到客户电脑上（任意目录均可）
2. **右键 exe → 以管理员身份运行**
3. 程序自动依次执行 7 个修复步骤并做结果校验，全程无需干预
4. 看到 `[SUCCESS] All checks passed!` 即修复成功，**建议重启电脑**后再试装 MSI

> 若提示没有管理员权限，程序会直接退出并给出英文提示，此时请按第 2 步重新运行。

### 6.2 拖放强制安装（无视后缀）

1. 在资源管理器中找到要安装的文件（后缀是 `.msi` 最好，被改成其他后缀也没关系）
2. **用鼠标把它直接拖到本程序的 exe 图标上**松开
3. 程序识别到命令行参数后自动进入安装模式，调用 `msiexec /i "该文件"` 开始安装
4. 安装界面出现后，本程序的窗口可以任意关闭，不影响安装继续执行

> 该模式**不需要**管理员权限启动本程序；如果普通方式启动安装失败，程序会自动改用 `runas` 提权重试，届时会弹出 UAC 提示，点"是"即可。

### 6.3 交互菜单方式

直接双击运行 exe（以管理员身份），程序会先执行一次完整修复，然后进入菜单：

`==================== Main Menu ====================`\
`  1. Re-run MSI association repair`\
`  2. Force install MSI file (ignore extension)`\
`  3. Exit`\
`====================================================`\
`TIP: Drag & drop any file onto this EXE to install`

- 输入 **1**：重新执行一遍完整修复流程
- 输入 **2**：提示输入文件完整路径，此时可以**把文件直接拖进控制台窗口**（路径会自动填入），回车即开始安装
- 输入 **3**：退出程序

## 八、修复原理

本工具按以下顺序处理，每一步都对应一类常见的损坏点：

1. **停服务** —— 先停止 `msiserver`，避免修复过程中文件与注册表被占用
2. **重注册核心组件** —— 执行 `msiexec /unregister` 和 `msiexec /regserver`，重建 Windows Installer 的 COM 注册信息
3. **清除 UserChoice** —— 删除 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.msi\UserChoice`以及 `.DEFAULT` 用户下的同名项。 **这是本工具与网上批处理的最大区别**：Win10/11 的 UserChoice 子键里存有一个基于用户 SID 和 ProgId 计算的 `Hash` 值，系统读取时会校验该哈希；手工把 ProgId 改回去而不更新 Hash，系统会**直接忽略**这条关联，于是"改了注册表却依然无效"。
4. **重建文件关联** —— 写入 `HKCR\.msi` 默认值、`HKCR\Msi.Package\shell` 默认动作，以及 `install / open / repair / uninstall` 四个 `command` 子键；64 位系统上同时写入 `Wow6432Node` 分支，保证 32 位与 64 位程序都能正确调用 msiexec
5. **修服务配置** —— 恢复 `msiserver` 的 `ImagePath` 为 `"…\msiexec.exe" /V`（解决错误 1719），并重新调用 `msi.dll` 的 `DllRegisterServer`
6. **启服务** —— 重新启动 `msiserver`
7. **刷新外壳** —— 调用 `SHChangeNotify` 通知资源管理器关联已变更，**无需重启即可生效**

另外，程序内部对 `system32` 路径的访问会**临时关闭 WOW64 文件系统重定向**，确保 32 位程序拿到的是真正的 `C:\Windows\System32`，而不是被重定向到 `SysWOW64`。

## 九、常见问题 FAQ

**Q1：修复后过一段时间又坏了**？多为安全软件（360、电脑管家等）锁定文件关联导致。修复前先临时退出安全软件，修复成功后把本工具加入白名单。

**Q2：运行后日志里说 UserChoice 被锁定怎么办**？同上，临时关闭安全软件的"主页 / 文件关联保护"类功能后重新运行本工具。

**Q3：修复了还是装不上，报 1603 / 1619**？此时问题通常已不在文件关联，而在安装包或系统层面：

- 执行 `sfc /scannow`，再执行 `DISM /Online /Cleanup-Image /RestoreHealth` 修复系统文件
- 若日志提示加载 `msi.dll` 失败，说明该文件已损坏或丢失，可从相同版本的系统目录中拷贝 `msi.dll`、`msiexec.exe` 回 `system32`（64 位系统还需检查 `SysWOW64`）
- 用微软官方工具 **Microsoft Program Install and Uninstall Troubleshooter** 清理残留安装信息

**Q4：拖放没反应**？确认文件不是快捷方式、且路径中不含被系统禁止的字符；也可以改用菜单方式（选 2）把文件拖进控制台窗口，效果一样。程序使用系统 API 解析命令行参数，支持**带空格和中文的路径**。

**Q5：控制台为什么会是英文**？这是刻意的设计：中文控制台输出在部分精简版 / 修改版系统上必然乱码（代码页被改、字体缺失、`SetConsoleOutputCP` 被策略禁用等），因此控制台统一改用纯 ASCII 英文输出，**在任何系统上都不可能乱码**；需要看中文的话，直接打开同目录的 `MSI修复日志.txt`。

**Q6：可以只安装、不修复吗**？可以。直接把文件拖到 exe 上即可，程序不会执行修复流程，只做安装。

## 十、注意事项

- 修复模式**必须**以管理员身份运行，否则注册表与服务无法修改
- 该工具会修改 `HKEY_CLASSES_ROOT`、`HKEY_CURRENT_USER\...\FileExts\.msi`、`HKLM\SYSTEM\CurrentControlSet\Services\msiserver` 等位置，**请在企业环境中先做测试**
- 修复完成后建议重启一次，个别场景下外壳缓存需要重启才彻底刷新
- 本工具只负责"文件关联 + 服务配置 + 组件重注册"，**不修复损坏的安装包本身**；若安装包自身损坏，任何工具都无法安装
- 请勿在未获得授权的情况下在他人电脑上运行
